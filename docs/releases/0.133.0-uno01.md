# Uno Launcher 0.133.0-uno01

The island, Home's search and search over an app are one surface now, and Qwen can do tasks as well as answer.

## What's changed

### One assistant surface

- **Pull the island on into search.** Pull down about a thumb's width on the open island, or carry one pull from the pill that far past fully open, and search opens when you let go, growing from the island where it is. There is a tick as the pull crosses over. Over another app, open the island first, then pull: Android takes a long pull from the very top of the screen for itself.
- **Back in steps.** In search, Back clears what you typed, and the next Back closes search. This also fixes Back not closing Home's search at all.
- **The island's Search opens search.** With the island drawn above the status bar, its Search button opened the App Library; it now opens search, over Home or over the app you're in.
- **"Ready" goes straight to the answer**, over the app you're in, and clears once you have read it there (it used to stay).
- **The island steps aside for search over an app**, so the two are never on screen together, and the glass no longer shows a ghost of the island it grew from.
- **A reopened answer falls into place** over an app too. In 0.132.6 it was blank for a second, then appeared all at once.

Underneath, the island's open and part-open states, Home's search and the search over an app are views of one state with one table of what each gesture does, and both searches share one panel.

### Qwen can do tasks (off by default)

Switch on **Let Qwen do tasks** in Search settings, under Local assistant. It needs **Uno Lab 0.3.9**.

- Ask for something to be done ("note that the door code is 4411", "open the camera and start a 10 minute timer") and Qwen plans it in Uno Lab and the launcher does it, then says exactly what it did, with Undo where it can be taken back. Up to three steps.
- **Anything that leaves the phone asks first.** The first such action is **replying to a message from its notification**: you are shown who it goes to, in which app, and the exact words, and nothing is sent until you tap. Who it goes to is fixed before you are asked, so a message arriving meanwhile cannot redirect it. If nobody is waiting for a reply, or a name fits two people, Qwen asks instead.
- **Ask before every action** makes every action wait for a tap.
- Qwen never acts on something you did not give it: a web address or phone number it made up becomes a question.
- For a reply, the launcher keeps who each waiting message is from and in which app, in memory only and only while tasks are on. It never reads a message's words.
- What search already does instantly (a timer, the torch) still happens instantly; the model is asked only for what search cannot do itself. A plan takes about 5 to 8 seconds on a Pixel 10a.

### Fixes

- A crash at start when the island drew before anything else had set up the type styles.

## Notes: what this has and hasn't been tested on

**On a Pixel 10a** (GrapheneOS, Android 17), with signed builds of this version:
- The island opening, peeking and closing; both pulls into search on Home; the pull from the open and the part-open island over Clock.
- Back's three steps on Home and over Clock.
- The island's Search over Home and over Clock; "Ready" opening over Clock, with the answer cascading in, and clearing after.
- No search window left behind after repeated opens and closes.

**On the same phone, with the test build (Uno Dev) and Uno Lab 0.3.9:**
- A task end to end: "open the camera" planned, run, and reported, with Camera in front.
- The planner scored on 48 phrasings, plan only: 37 right (37 of 45 without the three reply phrasings, which the test build cannot offer). Known misses: "do not disturb on" planned as off, "text 555 0100" as a call, "dentist in 30 minutes for an hour" as a timer.

**On an emulator:** 62 island and search device tests. 1,318 unit tests pass; lint clean.

**Not seen on a phone:**
- **Replying to a message.** It is covered by 16 unit tests, including the message-arrives-while-you-decide case, but no reply has been sent from a real notification yet.
- The two new switches being flipped in the release build's settings.
