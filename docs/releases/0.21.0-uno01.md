# Uno Launcher 0.21.0-uno01

Pulling down on Home opens search, and the new Uno Keyboard.

## What's new

- **Pull down for search.** Pulling down on Home now works like iOS: from the **top edge** the left side still opens notifications and the right side the control panel, and a pull that starts **anywhere lower** opens search. Before, only the island's button opened search, and a pull from lower on the left opened Android's notification shade. Customize > Control panel & extras > Pulling down on Home keeps the two older behaviours as choices.
- **Uno Keyboard** (optional; turn it on in Android's settings, then select it). A glass-styled keyboard: magnified key previews (never in password fields), accents on long-press, caps lock, a numbers and symbols page, a repeating backspace, double-space full stop, a Return key that follows the field (Go, Search, Send, Next, Done), and a globe key to switch keyboards. It follows light/dark, the Color from wallpaper accent, and your Haptics and Sounds switches.
  - It is strictly local: nothing typed is stored, learned, logged or sent, and its code has no network access (a unit test fails the build if any keyboard file imports network, logging, file-writing or clipboard code). Because Uno's APK also holds the internet permission for feeds you add, turn off Network for Uno in GrapheneOS if you want a hard guarantee (feeds will stop fetching).
  - It has **no autocorrect, prediction, swipe typing, emoji or voice input**, and is English (US) only, so I would not make it your main keyboard yet.

## Everything from 0.20.0 is still here

Widget stacks, Spotlight search, search suggestions (F-Droid, Aurora, your browser), haptics and sound design, and the island's rings.

## Notes: what this release has and hasn't been tested on

Tested only on an emulator that renders in software (slow, with occasional "not responding" dialogs); real-hardware performance is unmeasured.

Verified on the emulator: a pull starting low on Home opens search (even with the old notifications choice saved), a pull from the top right opens the control panel, and the routing rules by unit test. The keyboard was typed on with real taps: letters, shift, the numbers page, accents, preview bubbles, backspace repeat, and the field's Done key; its model and privacy rules are unit-tested.

Please check on your Pixel:

- **The pull-down feel.** Is 22% of the screen the right height for "top edge", and does a pull from the top left still open notifications (needs the optional shade gestures turned on)?
- **The keyboard**, in the apps you actually use: key size under your thumbs, the preview and accent popups near the screen edges, password fields, and whether the system's "show on-screen keyboard" behaviour with a physical keyboard is what you expect.
- **Search suggestions with F-Droid, Aurora and Vanadium**, which I could not test on an emulator, and everything still unverified from earlier releases (stacks with your widgets, haptics and sounds, the island ring at your cutout, the tilt highlight, split screen).
